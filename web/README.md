# Pong world-model demo (web/)

Play Pong in the browser against the trained agent, which runs entirely
client-side via onnxruntime-web. You control the LEFT paddle; the model drives
the RIGHT paddle by looking at the same 4-frame 64x64 pixel stack it saw in
training and picking an action with `argmax(logits)` every tick.

## Run it

```bash
cd web
python -m http.server 8000
# open http://localhost:8000
```

A real HTTP server is required: opening `index.html` via `file://` blocks the
`fetch` of the `.onnx` model files (and of the onnxruntime wasm backend), so
you would always get the scripted fallback opponent.

## Controls

| Input                        | Action                 |
|------------------------------|------------------------|
| `W` / `ArrowUp` (hold)       | move your paddle up    |
| `S` / `ArrowDown` (hold)     | move your paddle down  |
| on-screen ▲ / ▼ buttons      | same, for touch screens|

The match is endless: after every point the score (DOM scoreboard above the
canvas, never drawn into the 64px frame) updates and the ball re-serves.

## The two models

- **baseline** (`model_baseline.onnx`) — policy trained with PPO directly in
  the real pixel environment.
- **dream** (`model_dream.onnx`) — policy trained inside the learned world
  model ("in the dream") and then transferred to the real game.

Switch between them live with the dropdown. The status line shows which model
is loaded and the rolling-mean inference latency in ms.

## Files

- `index.html` / `pong.js` — zero-build vanilla JS; the simulation is an exact
  port of `pong/env.py` physics (same step order, same `floor(x+0.5)`
  rounding), reading every constant from the generated `constants.js`.
- `constants.js` — GENERATED by `scripts/export_constants.py` from
  `config.ENV`; if it is missing the page shows a red banner and halts.
- `model_baseline.onnx` / `model_dream.onnx` — exported by
  `scripts/export_onnx.py`. If a model file is missing or fails to load, an
  amber "model not loaded — scripted fallback" banner appears and the right
  paddle is driven by the scripted tracker (speed `C.opp_speed`, deadzone
  `C.opp_deadzone`), so the game is always playable.
